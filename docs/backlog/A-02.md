## What the backlog says

> `replayJournalEntries` handles five of eighteen journal types. `JournalAwakeableCreated`,
> `JournalSleepStarted`, `JournalSubWorkflowStarted` each have one write site and **zero read sites**.
>
> - **subworkflow** — restart spawns a duplicate child. Real duplicate side effect.
> - **awakeable** — restart re-mints via `uuid.New()`; the token you handed out is orphaned pending forever.
> - **sleep** — restart restarts the full duration.
>
> All three are blocking now: agents inside the engine will use sub-workflows for composition and
> awakeables for gates.

## Premise status

**Subworkflow — VERIFIED-REPRODUCED (F-01.2, 2026-08-11).** EXECUTED against real Go 1.26 (in a
`golang:1.26` container; there is no host Go), checked-in failing test at
`internal/actors/f01_2_verification_test.go`. All four links hold: a pending system/subworkflow leaves
`step:started` with no completion; `findPendingThreads` matches it; `replayPendingThread` re-issues it
**with the original execID, not a new one**; interception fires again and a second child is spawned.

Two limits the verifier stated, and they matter: (i) the defect is **synchronous sub-workflows only** —
with `async=true`, `handleSubWorkflowAction` calls `SetResultFor` at
`internal/actors/workflow_handler.go:936`, journalling `step:completed`, so `findPendingThreads` never
sees it (READ, not executed); (ii) no process was killed, no ergo runtime, no Postgres — "restart" here
means rebuilding the aggregate from the persisted journal. F-02 supplies the real thing.

**Awakeable — UNVERIFIED, and the entry's wording is contradicted by a read.** Per the skill pack's
Traps: `internal/handlers/resolve_awakeable.go:66` resolves via the awakeable's *own stored*
`ExecID`/`ThreadID`, so a pre-crash token still routes after a restart — it is not orphaned. What was
READ instead: `handleSystemWait` (`internal/actors/workflow_handler.go:727`) mints
`uuid.New().String()` on **every** invocation with no read of `JournalAwakeableCreated`. Verify both
halves — the failing clause and the replacement — before re-scoping.

**Sleep — UNVERIFIED.** Nobody has looked.

## Decisions

The backlog does not mandate an ADR. **ADR-0010** (Durable execution via an append-only journal)
governs replay and its "which entry types are replayed" account needs correcting; it is `Accepted` and
immutable, so a change to the awakeable *minting contract* is a new ADR (next free number 0035) — the
planner's call. Also interacts with **ADR-0032** (Sub-workflow composition) and **ADR-0023** (Timeout
enforcement via actor timers).
