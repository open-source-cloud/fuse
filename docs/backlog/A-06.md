## What the backlog says

> Memory driver returns the live pointer; postgres rebuilds per call. Return a deep copy from memory and
> assert both drivers behave identically. A-05 fixes the durable half of this; A-06 fixes the live half.
> Both are needed.

F-01.3, whose premise this is, states it as:

> `graph_memory.go:FindByID` returns the shared `m.graphs[id]` pointer live `Workflow`s hold, so
> `updateVersioned → graph.UpdateSchema` rewrites a running run's topology in place.

## Premise status

**REPRODUCED (F-01.3, 2026-08-11), and the driver-parity half was EXECUTED against a real Postgres 17.**
The postgres driver is immune; the memory driver is not. Checked-in failing tests, executed against real
Go 1.26 in a `golang:1.26` container:

- `internal/services/f01_3_verification_test.go`
- `tests/functional/f01_3_verification_test.go`
- `tests/functional/f01_3_verification_pg_test.go`

No production code was modified.

**Scope refinement.** The in-place rewrite is reachable **only** through the `Upsert`/`updateVersioned`
path. `SetActiveVersion` (`internal/repositories/graph_memory.go:158-163`) and `Rollback`
(`internal/services/graph_service.go:154-161`) both build a **new** `Graph`, so activate and rollback do
not rewrite live runs — they leave them on a *stale* graph instead, which is A-05's half. **A-06 can
proceed on its premise unchanged.**

**Two fix shapes are acceptable and the tests were written to accept either:** (1) clone-on-read in
`graph_memory.go:FindByID`, mirroring the idiom already present at `FindByIDAndVersion:89-90`
(`schema := sv.Schema.Clone()` then `workflow.NewGraph(&schema)`); or (2) make `updateVersioned` build
and `Save` a new `Graph`. Pick one on merit; do not reshape the tests to force a shape.

## Decisions

Neither an ADR nor a SpecKit spec — this is a bug fix inside one repository plus a parity assertion.
Interacts with **ADR-0003** (In-memory repositories by default, Postgres optional), which is what makes
driver parity a contract rather than a nicety, and with **ADR-0014** (Immutable schema versioning with
active-version pointer). No public API change, so the changelog rule does not bite here.
