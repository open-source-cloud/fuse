## What the backlog says

> 1. `internal/actors/workflow_func.go` — node span context discarded (`_ = nodeCtx`), so function code cannot create child spans or inject `traceparent` outbound. **Now critical**, because it is the seam every SDK crosses.
> 2. Restart with a pending `system/subworkflow` spawns a second child — `findPendingThreads` matches `step:started` without completion, `replayPendingThread` re-issues, interception fires again.
> 3. `graph_memory.go:FindByID` returns the shared `m.graphs[id]` pointer live `Workflow`s hold, so `updateVersioned → graph.UpdateSchema` rewrites a running run's topology in place.
>
> **Done when:** each is a checked-in failing test on `main`, or a written note that it did not reproduce and why.

Scope corrections, each of which changes the task that inherits the finding:

- **F-01.1 → A-04.** `_ = nodeCtx` (`workflow_func.go:96`) is a **symptom, not the defect**: removing it
  fixes nothing, because nothing downstream accepts a context and `pkg/workflow.ExecutionInfo` has no
  context field and no methods at all. A-04 item 3 is a **public `pkg/` API change**. Executed evidence:
  a node function run through the real production execute path with a real OTel provider injects an
  **empty** carrier, while the same provider injects a trace id from the live node span.
- **F-01.2 → A-02, regression-tested by F-02.** All four links reproduced: pending system/subworkflow
  leaves `step:started` with no completion → `findPendingThreads` matches → `replayPendingThread`
  re-issues with the **original** execID (not a new one) → interception fires again → second child.
  Synchronous sub-workflows **only**: with `async=true`, `handleSubWorkflowAction` calls `SetResultFor`
  (`workflow_handler.go:936`), journalling `step:completed`, so `findPendingThreads` never sees it (read,
  not executed). Verifier's limits: no process killed, no ergo runtime, no Postgres — "restart" meant
  rebuilding the aggregate from the persisted journal. That is exactly what F-02 must supply for real.
- **F-01.3 → A-06.** Reproduced; the driver-parity half was executed against a real Postgres 17 (postgres
  driver immune, memory driver not). The in-place rewrite is reachable **only** through the
  `Upsert`/`updateVersioned` path — `SetActiveVersion` and `Rollback` both build a new `Graph`, so
  activate and rollback leave live runs on a *stale* graph instead. A-06's premise stands unchanged; at
  least two fix shapes are viable (clone-on-read in `FindByID`, or `updateVersioned` building and saving
  a new `Graph`) and the tests are written to accept either.

## Decisions

No ADR for F-01 itself. **A-04** now needs one: adding a context to `pkg/workflow.ExecutionInfo` has
design tension with **ADR-0027 · Async tool invocation via a sub-execution channel** (Proposed), which
says per-execution runtime capability must *not* be re-added as a field on `workflow.ExecutionInfo` —
settle that before writing code. F-01.2 interacts with **ADR-0010 · Durable execution via an append-only
journal** and **ADR-0032 · Sub-workflow composition**; F-01.3 with **ADR-0014 · Immutable schema
versioning**. Next free ADR number is **0035**.
