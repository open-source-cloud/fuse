## What the backlog says

> Make the HTTP transport real: `MapToRegistryPackage` stops registering non-internal functions
> metadata-only; a remote node dispatches per B-01, returns `NewFunctionResultAsync()`, releases its
> pool worker, and resumes on callback. Inject `traceparent`. Validate that the callback's exec is
> genuinely pending and reject duplicates and stale execIDs.
>
> This is the generalised, specified version of what the previous backlog called "a generic async HTTP
> node". Same code, promoted from workaround to product surface.

## Premise status

**net-new construction.** Nothing to reproduce; there is no HTTP transport to be broken. What the
routing table records as CONFIRMED is the *gap*: `loaded_package.go:41` is the `function %s has no
transport` dead end, and `async_function_result.go:HandlePost` does no pending-state, duplicate or
staleness validation.

**This is bigger than the entry implies, for one reason.** F-01.1 (REPRODUCED, executed against real
Go 1.26) showed that "Inject `traceparent`" is not a line of transport code: nothing downstream can
accept a context. `LoadedPackage.ExecuteFunction` (`internal/packages/loaded_package.go:35`),
`FunctionTransport.Execute` (`internal/packages/transport/internal.go`) and the **public**
`type Function func(*ExecutionInfo) (FunctionResult, error)` (`pkg/workflow/function.go:4`) are all
context-free, and `pkg/workflow/ExecutionInfo` has no context field. A-04 owns that four-hop public
`pkg/` API change and it carries an unresolved ADR-0027 conflict. **B-02 cannot inject anything until
A-04 lands.** Plan around the dependency; do not re-litigate it here.

## Route

**Blocked on B-01, A-04 and A-10.** All three are open.

1. `fuse-implementation-planner` — hand it the published B-01 spec (clause ids), the F-01.1 verdict and
   the A-04 outcome. Its `PROTOCOL IMPACT` section must map every behaviour to a spec clause id.
2. `fuse-go-implementer`.
3. `fuse-code-reviewer`.

**Deviation to hold:** if the plan needs a wire behaviour B-01 did not specify — most likely the
error-taxonomy field, since the engine has no representation for business-vs-infrastructure error today
— **stop and route back to `fuse-protocol-spec-author` for a versioned spec revision**. Never invent a
clause in Go. Also settle with F-02/A-03 before choosing resume behaviour: an async dispatch is
journalled `step:completed` at `internal/actors/workflow_handler.go:275`, *before* the `Async` check at
`:277`, so `findPendingThreads` will not see an in-flight remote call as pending.

## Done when

Derived from the task text; the backlog gives no "Done when" list.

- [ ] A non-internal registration produces a `LoadedFunction` with a non-nil remote `Transport`, surviving `Registry.Register`'s non-downgrade rule.
- [ ] A remote node dispatches per the B-01 envelope clause, returns `NewFunctionResultAsync()`, and releases its pool worker for the whole in-flight duration.
- [ ] The run resumes on callback, with the result routed exactly as a sync internal function's would be.
- [ ] `traceparent` is injected outbound and observable at the worker (requires A-04).
- [ ] The callback route rejects: unknown workflow, unknown/malformed execID, an exec that is not pending, an exec belonging to a different workflow, and a duplicate submission.
- [ ] Behaviour is asserted under `DB_DRIVER=postgres` with a filesystem object store, not memory only.
- [ ] Every implemented behaviour cites the B-01 clause id it satisfies.
- [ ] `make lint && make build && make test` green.
