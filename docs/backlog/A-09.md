## What the backlog says

> Every payload-carrying journal entry is one object-store PUT. No threshold, no inlining, no
> compression, no dedup. A 200 KB transcript is re-PUT on every `step:started` whose input includes it
> and every `step:completed` whose result includes it, plus into `output.json` on every `Save`. At 50
> concurrent runs × ~12 steps: ~600 PUTs, ~120 MB per round. `LoadAll` re-fetches the whole payload
> graph on every resume, and A-07's duplicates make each restart heavier than the last.
>
> Two independent changes: **inline small payloads** in the PG row below a threshold;
> **content-address large payloads** by hash so an unchanged transcript is stored once and referenced N
> times. The second alone removes most of the amplification for conversational workloads.

## Premise status

UNVERIFIED — stage 1 must run `fuse-premise-verifier` before any code. The arithmetic in the entry is a
projection, not a measurement: nobody has counted PUTs for a real run. The verifier's job here is
unusual — the defect is a **cost/throughput property**, not a wrong answer — so the reproducing artefact
is a counting or benchmark test (`make test-benchmark` exists), not a failing assertion about output.

Ask it for two separable numbers: PUTs per step for a payload-carrying entry, and PUTs for one unchanged
payload carried across N steps. The second number is what content-addressing collapses.

## Route

Standard pipeline, with a research stage — this one spans the journal, the workflow save path, the trace
writer and the object store.

1. `fuse-premise-verifier` — measure, do not assert. Two numbers, as above.
2. `fuse-engine-researcher` — every write site that produces a ref, every read site that resolves one,
   and whether any ref is persisted anywhere a rewrite would strand it (existing rows must stay
   readable).
3. `fuse-implementation-planner` — with both. **It must state whether the two changes are one PR or
   two.** The backlog names them as "two independent changes" and says the second alone carries most of
   the benefit; "one task, one PR" argues for a deliberate call rather than drift.
4. `fuse-go-implementer`, then `fuse-code-reviewer`.

## Decisions

**Likely an ADR.** Content-addressing changes what an object-store ref *means*, and refs are already
persisted in journal rows, so this is costly to reverse and needs a compatibility story. It extends
**ADR-0019** (Externalize large payloads to a pluggable object store), which is `Accepted` and therefore
immutable — a new ADR, not an edit. Also interacts with **ADR-0010** (Durable execution via an
append-only journal). The planner makes the final call; next free ADR number is 0035 (coordinate with
A-03, A-04, A-05, A-11).

`pkg/objectstore/` is a public package — the changelog rule applies and **there is no CHANGELOG file in
this repo**; raise it with the maintainer rather than inventing one.
