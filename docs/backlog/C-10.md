## What the backlog says

> Today `idempotency/store.go` is trigger-level only. Nothing derives a key from
> `(runID, execID, attempt)`, while the resume path re-executes pending steps — at-least-once with no
> dedup beneath it. `ExecutionInfo` already carries `WorkflowID` and `ExecID` into every function, so
> the raw material is there. Derive a stable key, put it in the protocol envelope, and let the SDKs
> dedupe on it transparently.

## Premise status

**READ-confirmed for the gap; UNVERIFIED by execution; net-new for the convention.**

From the `remote-node-protocol` pack: the only idempotency keys that exist are trigger-level and
deterministic — `cron:<schemaID>:<RFC3339 minute>` (`cron_scheduler.go:86`) and
`evt:<schemaID>:<type>:<source>:<sha256(json(data))[:16]>` (`internal/actors/event_trigger.go:120-124`), both through
an atomic `CheckAndSet`. **Nothing derives a key from `(workflowID, execID, attempt)`.**

The third component is the real problem, and it is why A-08 is a practical prerequisite even though the
backlog does not declare it: automatic retries **reuse** the same `ExecID`, `RetryTracker` is in-memory
and never journalled as a number, and manual `RetryNode` mints a fresh `ExecID`. The attempt has to be
threaded through `workflowactions.RetryFunctionAction.Attempt` (which already exists, set in
`HandleNodeFailure`) into `messaging.ExecuteFunctionMessage` and then into `ExecutionInfo`.

Two durability facts that make the key load-bearing rather than decorative, from
`durable-execution-internals`: `replayPendingThread` re-issues the **original** execID with no marker
(invariant 4, "replayed steps must be idempotent — nothing beneath them dedupes"), and an async-parked
step is journalled `step:completed` at dispatch, so the pending-step machinery does not even see it.

## Route

**Deviation: this starts at `fuse-protocol-spec-author`, not the planner.** The key goes into the
remote-node **wire envelope** (B-01 decision 2) and is the thing SDKs dedupe on (B-01 decision 5,
which is A-03's delivery-guarantee decision). Once B-01 is published and an SDK exists, changing the
key format breaks strangers.

1. `fuse-protocol-spec-author` — the key's derivation, stability rules and envelope field, settled in
   the B-01 spec. Not `TBD`.
2. `fuse-premise-verifier` — the executed gap: a resumed pending step re-invokes with nothing
   deduping beneath it. Postgres only.
3. `fuse-implementation-planner` → `fuse-go-implementer` → `fuse-code-reviewer`.

**A-08 first, or the key is two-thirds of a key.** Sequence it, or state explicitly that v1 of the key
omits `attempt` and record what that costs — do not discover it during implementation.

## Done when

Derived; the backlog gives no "Done when".

- [ ] The key derivation is written into the B-01 spec, versioned, with stability rules (what changes
      it, what must not).
- [ ] A stable key is derivable from `(runID, execID, attempt)` and reaches function code — which means
      `attempt` reaches `ExecutionInfo`.
- [ ] The key is carried in the protocol envelope so an SDK can dedupe transparently.
- [ ] A replayed pending step presents the **same** key as its pre-crash dispatch — asserted under
      `DB_DRIVER=postgres` with a real restart.
- [ ] Consistent with A-03's chosen delivery guarantee; the two do not state different things.
- [ ] Covered by the B-05 conformance suite ("retry with a stable idempotency key" is already one of
      its listed cases).

## Out of scope

- **B-01** owns the spec as a whole; C-10 contributes one decision to it, and does not reopen the
  others. **A-03** owns the delivery-guarantee decision and its ADR.
- **A-08** owns the attempt counter and rebuilding `RetryTracker` on replay. Do not implement it here.
- **B-02** owns the transport that carries the envelope. **B-05** owns the conformance suite.
- Do not extend the trigger-level idempotency store's semantics (TTL, scope) as a drive-by — ADR-0017
  owns those.

## Decisions

The **B-01 spec** is the primary artefact; an **ADR** may not be needed separately if A-03's ADR already
records the delivery guarantee this key serves — confirm rather than duplicating. Interacts with
**ADR-0017 · Idempotent triggering via CheckAndSet with TTL** (the existing trigger-level decision this
extends to node level; it will need an amendment or a superseding ADR if the semantics diverge),
**ADR-0022 · Retry and error-handling model** (the attempt component), and **ADR-0010 · Durable
execution via an append-only journal** (replay re-issues the original execID with no marker). Next free
ADR number is **0035**.

`pkg/workflow/execution_info.go` is a **public package** — the changelog rule applies, and **there is no
CHANGELOG file in this repo**; raise it with the maintainer rather than inventing a destination. Note
**A-04** is separately about to change the same struct (F-01.1 established that adding a context there
is a public `pkg/` API change with ADR-0027 tension). Coordinate; do not let two tasks reshape
`ExecutionInfo` in opposite directions.
