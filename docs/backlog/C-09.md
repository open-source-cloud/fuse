## What the backlog says

> `GET /v1/workflows/{id}` returns `{workflowId, status}`. Snapshot and trace persist only in
> `sendWorkflowCompleted`. No SSE, no WebSocket; `memory_bus.go` is in-process and unreachable
> externally.
>
> With everything inside the engine, this is no longer optional: the console has nothing to render
> without it. Minimum: `GET /v1/workflows/{id}/state` built from the journal — thread positions,
> completed steps, pending steps, open gates. Streaming is a separate later task; do not conflate them.

## Premise status

**READ-confirmed for the gap; UNVERIFIED by execution. One scope correction the entry does not carry.**

- Confirmed: `GET /v1/workflows/{workflowID}` (`mux_worker.go:220`) returns
  `dtos.GetWorkflowResponse{workflowId, status}` and nothing else (`get_workflow.go:49-64`). There is
  **no** `/v1/workflows/{id}/state` route today, and no `/status` route either, whatever older prose
  says — trust `mux_worker.go`.
- Confirmed: snapshot and trace are persisted **only** from `sendWorkflowCompleted`
  (`workflow_handler.go:518-519`), i.e. at terminal state; `GET /v1/workflows/{id}/trace` 404s until the
  run ends.
- **Scope correction.** `GET /v1/workflows/{id}/snapshot` (`mux_worker.go:240`) already serves the
  persisted snapshot **or, when `snapshot_ref` is unset, builds one live** from `journalRepo.LoadAll` +
  `BuildExecutionSnapshot` (`internal/handlers/get_workflow_snapshot.go:59-98`). That is the closest
  thing to a mid-flight read model that exists — the backlog entry does not mention it. Its known
  weakness is precisely what C-09 must fix: its `aggregatedOutputs` comes from a repo-reconstructed
  `Workflow` and is therefore **empty under Postgres**. Verify whether C-09 is a new endpoint or a
  repair-and-extension of this one before designing either.
- Also relevant: `SnapshotTimelineEvent` (`internal/workflow/execution_snapshot.go:47`) has **no `Data`
  field**, which is why open gates are invisible (that is **C-07**'s complaint from the other side).

## Route

1. `fuse-premise-verifier` — sub-claims: (a) no route reports thread positions, pending steps or open
   gates mid-flight; (b) the existing snapshot route's `aggregatedOutputs` is empty under Postgres.
   Postgres only — under memory the repository hands back the live object and the gap hides.
2. `fuse-engine-researcher` — is C-09 a new endpoint or the repair of `/snapshot`? What the journal can
   answer purely, and what needs the live actor. **Projections are pure** — `BuildTrace` and
   `BuildExecutionSnapshot` both say so in their doc comments; new read logic takes `[]JournalEntry`
   and returns a value.
3. `fuse-implementation-planner` → `fuse-go-implementer` → `fuse-code-reviewer`.

## Out of scope

- **Streaming.** The entry says it plainly: "Streaming is a separate later task; do not conflate them."
  No SSE, no WebSocket, no change to `memory_bus.go`.
- **C-07** owns exposing awakeable ids. If C-07 lands first, open gates arrive with ids attached;
  if C-09 lands first, coordinate so the two surfaces agree. Do not build both endpoints under one id.
- **A-07** owns the duplicate-append defect that inflates the snapshot timeline by a full copy per
  restart (`execution_snapshot_builder.go:32`). C-09 will make that visible; it does not own the fix.
- **D-02** owns rendering. **C-04** owns cost attributes on the trace.
- Do not add `Data` to the snapshot event and simultaneously redesign the timeline — pick one.

## Decisions

Probably **neither** an ADR nor a SpecKit spec if C-09 extends the existing snapshot projection. It
tips to an **ADR** if it introduces a separate read-model store or a materialised projection rather than
reading the journal on demand — a CQRS split is costly to reverse. Interacts with **ADR-0010 · Durable
execution via an append-only journal** (the source of truth this projects), **ADR-0020 · Observability:
metrics, tracing, execution traces** (what the persisted trace is for, and how it differs from this),
and **ADR-0019 · Externalize large payloads to a pluggable object store** (a mid-flight read fetches the
payload graph — watch what it costs, cf. A-09). Next free ADR number is **0035**.

**Public HTTP API addition:** the changelog rule applies and **there is no CHANGELOG file in this
repo** — raise it with the maintainer rather than inventing a destination.
