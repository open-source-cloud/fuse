## What the backlog says

> `DB_DRIVER=postgres` with default `OBJECT_STORE_DRIVER=memory` yields durable journal rows whose
> `input_ref`/`result_ref`/`data_ref` point into a store that dies with the process. `LoadAll` then fails
> on every payload fetch and nothing is recoverable. Silent, and it looks correct until the first restart.
>
> Extend `Config.Validate` to reject persistent-DB + ephemeral-object-store and any other mismatched
> pair, naming both variables in the error.

## Premise status

**UNVERIFIED — stage 1 must run `fuse-premise-verifier` before any code.** Two halves, and they need
different evidence:

- *The guard is absent.* READ, recorded in the routing table: `Validate` returns `nil` for every
  combination except the etcd pairing. Cheap to re-confirm by reading.
- *The consequence — "nothing is recoverable".* UNVERIFIED. Nobody has run `DB_DRIVER=postgres` +
  `OBJECT_STORE_DRIVER=memory` across a restart and watched `LoadAll` fail. The verifier should produce
  that failure (it does not need process death; a second process against the same DSN with a fresh
  in-memory store is enough), because the error message the fix emits should name what actually breaks.

Related trap worth carrying into the fix, recorded in `.agents/agents/fuse-e2e-harness-engineer.md`
(read, not executed): `internal/app/di/objectstore.go` recognises only `filesystem` and `s3` and falls
through to the **memory** store for any other string, silently — so a typo produces the same
unrecoverable configuration by a second route. Whether an unknown driver string should also be an error
is a scoping question for the plan, not a licence to redesign the object store.

## Route

Default pipeline, short. 1 · `fuse-premise-verifier` — hand it the two sub-claims above split apart
(guard absent / restart unrecoverable). 2 · **skip** `fuse-engine-researcher`: single-file change, one
subsystem. 3 · `fuse-implementation-planner` with the verdict block — it must decide the exact matrix of
rejected pairs and whether unknown driver strings are rejected too. 4 · `fuse-go-implementer`, failing
test first. 5 · `fuse-code-reviewer`. 6 · gates `make lint && make build && make test`; add
`make test-functional` with `DB_POSTGRES_DSN` exported, since the premise is persistence-shaped.

## Out of scope

Not A-09 (inlining and content-addressing payloads) — F-03 only refuses a bad pair, it does not change
how payloads are stored. Not F-02: do not build a restart harness here; if the verifier wants restart
evidence it uses a second process by hand and says so. Do not add or rename object-store drivers, do not
change any default value, and do not "fix" the silent memory fallback in the same PR unless the plan
explicitly scopes it in — one task, one PR.

## Decisions

**Neither an ADR nor a SpecKit spec** — this is a config guard on a `fix/` branch. It enforces
**ADR-0019 · Externalize large payloads to a pluggable object store** and interacts with **ADR-0003 ·
In-memory repositories by default, Postgres optional** (the reason the two defaults can disagree at all)
and **ADR-0010 · Durable execution via an append-only journal** (whose refs are the things that dangle).
Environment variables are public surface: the backlog's "public API changes need a changelog entry" rule
applies, and **there is no `CHANGELOG` file in this repo** — raise that with the maintainer rather than
inventing one. Next free ADR number is **0035** if the plan turns out to need one.
