## Premise status

**net-new.** Nothing to reproduce in `core/`; stage 1 does not run. Three Core-side constraints, none of them D-03's to fix:

- **No external event feed.** `internal/events/memory_bus.go` is in-process and unreachable from outside the engine, and **C-09** defers streaming to a later task. "Server-authoritative sync" has no server feed to be authoritative over yet.
- **The only gate route is resolve.** `POST /v1/awakeables/{awakeableID}/resolve` (`mux_worker.go:270`, handler `internal/handlers/resolve_awakeable.go:55`) rejects a non-pending awakeable with 400 `"awakeable is not in pending status"` (`:72`) — verified this session. That is a last-writer-loses guard, **not** a claim: it stops a double *resolve*, not two people spending an hour on the same approval.
- A caller cannot learn the awakeable id at all today — **C-07**.

Tier A is not green: F-01 completed 2026-08-11 with all three findings REPRODUCED against real Go 1.26.
