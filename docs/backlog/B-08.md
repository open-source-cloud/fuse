## What the backlog says

> Register, health, deregister, drain. What happens when a worker is unreachable — how long a step
> waits, what the error taxonomy says, whether the run fails or parks. Also multiple workers behind one
> capability, and versioned capability rollout without breaking in-flight runs (interacts with A-05).

## Premise status

**net-new.** Nothing to reproduce; the routing table's instruction is "VERIFY what registration exists
today before designing around it", and the `remote-node-protocol` pack answers that by reading:

- Registration is a plain upsert — `internal/services/package_service.go:80`: `Validate` → repo `Save` →
  `Registry.Register`. No health check, no deregister, no drain, no TTL, no heartbeat.
- There is **no DELETE route for packages**: `internal/actors/mux_worker.go:120-121` declares `GET, PUT`
  only, although `internal/repositories/postgres/package.go:162` implements `Delete`.
- `FindAll`/`FindByID` with `Load: true` backfill the registry **only** `if !packageRegistry.Has(id)`,
  so a GET never refreshes an already-registered capability — updates must go through `Save`.
- "Worker unreachable" has **no error class**. It would surface as a generic `FunctionError` and be
  retried by the node's `RetryPolicy` (ADR-0022), indistinguishable from a business failure.
- Multiple workers behind one capability has no addressing model: `workflow.Package` carries
  `{ID, Functions, Tags}`.
- There is no capability versioning at all; the only versioning in the repo is graph-schema versioning
  (`internal/workflow/versioned_schema.go`), which A-05 pins per run.

`fuse-protocol-spec-author`'s operating procedure already requires it to re-confirm this inventory
before designing, so the verification the routing table asks for happens inside stage 1.

## Route

**Blocked on B-01** — lifecycle is wire surface, and its error taxonomy is B-01 decision 4.

1. `fuse-protocol-spec-author` — the agent's own contract names B-08 worker lifecycle as its spec-side
   territory. It must settle, as clauses: the lifecycle state machine, the health contract (who probes
   whom, how often, what a failed probe means), drain semantics for in-flight steps, the unreachable-worker
   error class, the wait/park/fail rule, multi-worker addressing, and capability-version rollout.
2. `fuse-implementation-planner` — with those clause ids.
3. `fuse-go-implementer` → `fuse-code-reviewer`.

**Deviation:** do not start at the planner. A lifecycle designed in Go and documented afterwards is
exactly the failure the "spec first" rule exists to prevent.

## Done when

Derived from the task text; the backlog gives no "Done when" list.

- [ ] Register, health, deregister and drain are each specified as a clause and implemented as a route or mechanism.
- [ ] An unreachable worker produces a distinct error class, not a generic `FunctionError` (requires B-01 decision 4).
- [ ] How long a step waits for an unreachable worker is bounded and configurable, and the rule for run **fails** vs run **parks** is explicit.
- [ ] Multiple workers can stand behind one capability, with a stated addressing and selection rule.
- [ ] A capability version can be rolled out without breaking in-flight runs — reconciled with A-05's per-run schema pinning.
- [ ] Drain lets in-flight steps finish rather than orphaning their callbacks.
- [ ] Driver parity: whatever a worker record needs is implemented for both memory and Postgres, with a migration if a table changes.
- [ ] `make lint && make build && make test` green; `make test-functional` with `DB_POSTGRES_DSN` exported.

## Out of scope

- **B-02** owns the transport itself and the callback validation.
- **B-03** owns the capability registry; B-08 governs the *worker* behind a capability, not the capability's definition.
- **A-05** owns pinning runs to a schema version. B-08 must interoperate with it, not implement it.
- **C-06** owns durable timers and the expiry sweeper. If "park" must survive a restart, that is a
  declared dependency on C-06 — raise it rather than building a second timer.
- The missing package `DELETE` route and `PUT`'s ignored path parameter are pre-existing defects with no
  owner. If deregister needs the route, that is in scope **as a specified clause**; fixing `PUT`'s path
  handling is not.

## Decisions

**Spec clauses first** (B-01's document, revised or extended). An **ADR is likely** for the
version-rollout rule, because it interacts with A-05's pinning decision and is costly to reverse — the
planner makes the call. Next free ADR number is **0035** (coordinate; several tasks are eyeing it).

Interacts with **ADR-0024** (registry with declarative metadata), **ADR-0022** (retry and error
handling — the unreachable class changes its inputs), **ADR-0023** (timeouts) and **ADR-0014**
(Immutable schema versioning with active-version pointer), whose model is the closest precedent for
capability versioning.

New public routes → Swagger annotations + `make swagger`, then `docs/API.md`. The changelog rule applies
and **there is no CHANGELOG file in this repo**; raise it rather than inventing one.
