**The biggest design risk in the backlog. ADR before code — the backlog says so explicitly.**

## What the backlog says

> `SetResultFor` writes `w.aggregatedOutput.Set(entry.FunctionNodeID, ...)` — keyed by **node ID, not
> exec ID**. A node that runs twice overwrites its own output; `SourceFlow` only ever sees the latest.
> The journal keeps every execution; the data plane does not. […] an agent loop is a cycle, every turn
> re-executes the same node, and each turn destroys the previous one's output in the data plane.
> Conversation history, per-turn selections, and any "reject step 2, keep 1, 3 and 4" correction are all
> unaddressable from inside the graph.
>
> **Do not start by re-keying the KV.** Two options, and the cheaper one is probably also the better one:
>
> - **(a) Turn state as a first-class Core concept** — a dedicated store (repository + journal entry
>   types) […] addressed by `(runID, agentNodeID, turn)`, entirely separate from `aggregatedOutput`.
>   Smaller blast radius, no breaking change to existing schemas, and it is a thing you want to exist
>   anyway (C-02).
> - **(b) Re-key `aggregatedOutput` by `(nodeID, execID)`** with a `latest` alias for compatibility and
>   mapping syntax for a specific execution. Correct and general; breaking-ish; needs its own ADR and a
>   migration story.
>
> Decide in an ADR before either. This is the one item that is expensive to reverse.

## Premise status

The keying is **confirmed by reading**: `internal/workflow/workflow.go:428` is
`w.aggregatedOutput.Set(entry.FunctionNodeID, result.Output.Data)` — node ID, not exec ID. Re-read
during dossier creation.

UNVERIFIED by execution: nobody has run a cycle and shown a second execution destroying the first's
output as seen from `SourceFlow`. Stage 1 owns that, and the resulting test is what any chosen option
must satisfy — it is the one artefact that survives whichever design wins.

## Route

**Deviation: an ADR sits between research and planning, and nothing is implemented before it lands.**

1. `fuse-premise-verifier` — a cycle, two executions of one node, and a `SourceFlow` mapping that can
   only see the latest. The test must be written **fix-agnostically** so it passes under either option.
2. `fuse-engine-researcher` — blast radius of each option: every reader above, whether any persisted
   artefact (snapshot, trace, child-completion message) encodes the node-ID keying, and what a
   customer's expr-lang condition would see under (b).
3. `write-adr` — next free number is 0035 (coordinate with A-03, A-04, A-05, A-09). Both options
   weighed; the rejected one recorded, not deleted. Settle with **C-02** first — the backlog says C-02
   "overlaps A-11(a) — do them together", so the ADR must know whether C-02 is in the same design.
4. `fuse-implementation-planner`, then `fuse-go-implementer`, then `fuse-code-reviewer`.

## The two options — do not decide here

**(a) Turn state as a first-class concept**, addressed by `(runID, agentNodeID, turn)`, separate from
`aggregatedOutput`. *For:* smaller blast radius; no breaking change to existing schemas; it is a thing
C-02 wants anyway. *Against:* two places node output can live, so "where do I read this from" becomes
conditional; it does not fix the general case of any node that runs twice, only the agent case; it needs
new journal entry types and therefore a migration.

**(b) Re-key `aggregatedOutput` by `(nodeID, execID)`** with a `latest` alias and mapping syntax for a
specific execution. *For:* correct and general — it fixes every re-executing node, not just agents.
*Against:* breaking-ish; needs its own migration story; and the readers above include
`expression.go:39`, which copies the raw KV into the expr-lang environment, so customer-authored
conditions are part of the compatibility surface.

**The backlog leans toward (a)** — it lists (a) first and says "the cheaper one is probably also the
better one". That is a stated leaning, not a decision. The ADR decides.

## Done when

## Decisions

**ADR required, before code — stated in the task text and echoed by the delivery pipeline's stage-3
table ("A-11 output addressing").** Interacts with **ADR-0013** (Workflow schema model and edge-based
input mapping — the `SourceFlow` contract this changes), **ADR-0015** (Conditional edge routing with

rather than inventing a destination.
