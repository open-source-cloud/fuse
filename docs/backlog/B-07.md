> Same contract, framework-idiomatic: service provider, route macro or attribute, queue integration for

> TypeScript-shaped, and Laravel is a large, underserved population for durable orchestration.

## Premise status

**net-new, and built outside `core/`.** Nothing here to verify or reproduce.

The load-bearing point is in the entry itself: this SDK exists to **prove the protocol is not
TypeScript-shaped**. Any place where the PHP implementation needs a behaviour B-06 got for free is a
spec defect — a clause that leaked a language assumption — and it goes back to
`fuse-protocol-spec-author` as a versioned revision, not into a per-language workaround. The queue
integration for the async path is the most likely place for that to surface: a queued job completes on a
different process from the one that acked, which stresses B-01's ack, idempotency and callback-auth
clauses harder than an in-process `await` does.

Engine-side reality remains: `pkg/transport/type.go` declares `HTTP` and `gRPC` and implements neither,
and an API-registered function is metadata-only (`internal/packages/loaded_package.go:41`). **B-02** is
what makes any of this callable.

## Route

**Blocked on B-02 and B-05.** Neither has started.

No pipeline agent in this repo writes PHP. The pipeline's jurisdiction is the spec:

1. `fuse-protocol-spec-author` — hand it every clause the Laravel/queue shape strains (ack across
   process boundaries, idempotent redelivery of a queued job, callback auth from a worker process the
   engine never called). It returns clause revisions; it writes Markdown only.
2. The SDK author implements outside this repo.
3. B-05's suite is the review gate, run unmodified. A scenario that needs per-language relaxation is a
   spec finding, not a suite edit.

## Done when

Derived from the task text; the backlog gives no "Done when" list.

- [ ] Framework-idiomatic surface: service provider, plus a route macro or attribute for marking a handler.
- [ ] Queue integration for the async path, so the ack and the completion can come from different processes.
- [ ] A redelivered queue job does not double-complete a step — idempotency per the B-01 clause.
- [ ] The full B-05 conformance suite passes against it, unmodified and with the same assertions B-06 passes.
- [ ] Every clause the PHP shape strained is either satisfied or filed as a spec revision — none worked around locally.
- [ ] A working example survives an engine restart mid-call, matching B-06's bar.

## Out of scope

- **Engine changes of any kind.** File findings against Core with the clause id; do not patch.
- **B-06** — the TypeScript SDK is a separate task and PR. Do not refactor the two into a shared core
  before both pass the suite.
- **B-05** — the suite is a prerequisite, built once, in Go, in this repo.
- **Protocol changes made unilaterally.** Once B-01 is published and an SDK exists, a change breaks
  strangers; it is a versioned revision by `fuse-protocol-spec-author`.

## Decisions

**No ADR in `core/`.** SDK-internal architecture is decided in the SDK's own repository. B-01's ADR is
the wire-level record.

If this SDK forces a B-01 clause to change, that revision needs a migration note for anyone already on
the previous version — and **there is no CHANGELOG file in this repo**, so raise the gap with the
maintainer rather than inventing a destination.
