## What the backlog says

> Spans exist (`workflow.execute`, `node.execute`) with `workflow.*`/`node.*` attributes. Missing:
> agent id, model, tokens in/out, cost, gate decision, tenant. LLM usage is Prometheus-only
> (`ai/usage.go`), disconnected from the trace.
>
> Follow OTel GenAI conventions where they exist; namespace the rest. Meter cost at the gateway,
> tagged run and step, so "what did this customer's Tuesday cost" is a query.

## Premise status

**READ-confirmed for the gap; UNVERIFIED by execution; net-new for the replacement.**

READ, from the `observability-tracing` and `capability-registry-and-agents` packs:

- LLM usage lands only on two Prometheus counters (`internal/metrics/registry.go:67-77`):
  `fuse_llm_tokens_total{function, provider, model, type}` and
  `fuse_llm_calls_total{function, provider, model, status}`. **No workflow id, exec id, node id,
  tenant or environment label on either**, and the recorder writes nowhere else. "What did this run
  cost" is unanswerable from any FUSE surface today.
- The OTel trace and the persisted `ExecutionTrace` are unrelated: migration
  `000006_create_execution_traces` has **no `trace_id`/`span_id` column**. Linking them is a new column
  and a new migration.

Three concrete blockers per wanted attribute, from the pack:

| Wanted | Blocker |
| --- | --- |
| graph node id | `messaging.ExecuteFunctionMessage` has no node-id field; recoverable handler-side via the audit log (the pattern at `workflow_handler.go:693`). |
| model, tokens, agent id | need a span reachable from `internal/packages/functions/ai`, which has **no** tracing dependency at all. Gated on **A-04**. |
| cost | **no data source.** `pkg/llm.Usage` carries token counts only; ADR-0029 defers the pricing table. This is why C-03 is a declared dependency. |
| tenant | no tenancy concept exists in Core — that is **D-01**. |

Stage 1's executed job is small and worth doing: scrape `/metrics` after a real `ai/chat` call and
assert that no label identifies the run.
