## What the backlog says

> `handleSubWorkflowAction` accepts and journals `input` and never passes it to the child. Wire it. Also
> add an output selector: the completion message carries the child's **entire** unfiltered per-node
> output map (`AggregatedOutputSnapshot()`), which balloons the parent's aggregated output and compounds
> A-09.
>
> Both are prerequisites for an agent composing and running a sub-workflow with parameters.

## Premise status

**UNVERIFIED as executed behaviour — stage 1 must run `fuse-premise-verifier` before any code.**

Two halves, and they are not in the same state. Both observations below are **READ** during dossier
creation, not executed:

1. **"Accepts … and never passes it to the child" — holds.** `workflowactions.RunSubWorkflowAction`
   declares `Input map[string]any` (`internal/workflow/workflowactions/action.go:81`);
   `handleSystemSubWorkflow` (`internal/actors/workflow_handler.go:888`) populates it from
   `action.Args["input"]`; and `handleSubWorkflowAction` (`:901`) then never reads it — the child is
   started with `messaging.NewTriggerWorkflowWithEnvMessage(action.SchemaID, childWorkflowID,
   a.workflow.Environment())` at `:930`, which carries no input.
2. **⚠️ "and journals `input`" — not observed.** The `JournalSubWorkflowStarted` entry appended at
   `internal/actors/workflow_handler.go:917-926` carries `Data{childWorkflowId, childSchemaId, async}`
   only. If input is journalled anywhere on this path, it is elsewhere. Have the verifier settle it: the
   difference decides whether the fix also changes what a replay of that entry can reconstruct.

**The output half holds by reading.** `notifyParentIfSubWorkflow` (`:865`) builds
`messaging.NewSubWorkflowCompletedMessage(...)` with `a.workflow.AggregatedOutputSnapshot()` at `:877` —
the child's whole per-node output map, unfiltered. Per the `capability-registry-and-agents` pack that
snapshot is a **shallow** copy (`pkg/store/kv.go` `Snapshot` is `maps.Clone`) and sub-workflow completion
is one of its three consumers, so the parent receives inner maps still shared with the child's live KV.
Flag that to the planner: it is a correctness question, not only a size one.

**A-01 is a hard prerequisite**: the input-carrying trigger path it owns
(`NewTriggerWorkflowWithInputMessage` exists, but `spawnWorkflowActor` takes three args and `Trigger`
hardcodes `Args: map[string]any{}`) is exactly what B-10 needs to hand input to a child.

## Route

**Blocked on A-01.** Do not wire input through a path A-01 has not built yet.

1. `fuse-premise-verifier` — three claims, numbered: (i) input is accepted and dropped; (ii) whether
   input is journalled at all; (iii) the completion message carries the child's entire unfiltered output
   map. Hand it the READ observations above so it confirms or contradicts them rather than re-deriving.
2. `fuse-implementation-planner` — with the verdict and A-01's outcome. It must say whether the input
   half and the selector half are one PR or two; the backlog names them as two changes under one id.
3. `fuse-go-implementer` → `fuse-code-reviewer`.

## Done when

Derived from the task text; the backlog gives no "Done when" list.

- [ ] Input declared on a `system/subworkflow` node reaches the child run and is visible to it under the reserved trigger key A-01 establishes.
- [ ] What is journalled for `subworkflow:started` matches what was actually passed (settled by stage 1).
- [ ] An output selector limits what the completion message carries back, so the parent no longer receives the child's entire per-node map; with no selector declared, behaviour is unchanged.
- [ ] The shallow-snapshot sharing between parent and child is either eliminated or explicitly documented as safe.
- [ ] Driver parity: asserted under `DB_DRIVER=postgres`, not memory only.
- [ ] A reproducing test lands first, failing, in the first commit.
- [ ] `make lint && make build && make test` green.

## Out of scope

- **A-01** owns the trigger payload end to end and the `trigger.*` reserved key. B-10 consumes it.
- **A-09** owns payload write amplification. B-10 removes one contributor to it; it is not the fix.
- **A-11** owns per-execution addressing of node output — the shallow-snapshot and re-execution problems
  in `aggregatedOutput` are its territory, and it is ADR-before-code.
- **A-02** owns replaying `subworkflow:started`; **B-09** owns the recursion depth guard. Same function,
  three different tasks — do not bundle.
- **V-b** (a second `subworkflow:started` for one exec id after resume) is unfiled in BACKLOG_V2.md.
  Tolerate it; do not fix it here.
- Choosing an agent composition model is gated behind F-02 by the backlog's HARD GATE. B-10 supplies a
  primitive; it does not decide how agents use it.

## Decisions

**Probably neither an ADR nor a SpecKit spec** for the input half — it is plumbing an existing field.
The **output selector is schema-visible surface**, so if it adds a declared construct to the workflow
schema it interacts with **ADR-0013** (Workflow schema model and edge-based input mapping) and
**ADR-0032** (Sub-workflow composition), both `Accepted` and therefore immutable — a material change is a
**new** ADR, next free number **0035** (coordinate; several tasks are eyeing it). The planner decides.

A schema-visible addition is public API: the changelog rule applies and **there is no CHANGELOG file in
this repo** — raise it with the maintainer rather than inventing one.
