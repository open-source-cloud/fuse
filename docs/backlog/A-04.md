## What the backlog says

> Three breaks. Inbound: `trigger_workflow.go:HandlePost` never reads headers, `startRootSpan` uses
> `context.Background()`; `ExtractCarrier` exists and is never called at the HTTP boundary.
> Handler→worker: works, add a regression test. Outbound: `_ = nodeCtx` discards the span context and
> `ExecutionInfo` has no `context.Context`, so function code cannot create children or inject
> `traceparent`.
>
> **This is the seam the SDKs cross.** A distributed engine whose selling point is traceability, that
> breaks the trace at exactly the boundary it invites you to extend across, is unsellable. Add the
> context to `ExecutionInfo`; B-02 depends on it.

## Premise status

**REPRODUCED (F-01.1, 2026-08-11), EXECUTED** against real Go 1.26 in a `golang:1.26` container.
Checked-in failing test at `internal/actors/f01_1_verification_test.go`. The evidence: a node function
run through the **real production execute path** with a real OTel provider injects an **empty** carrier,
while the same provider injects a trace id from the live node span. No production code was modified.

**Scope correction — read this before planning.** `_ = nodeCtx` at
`internal/actors/workflow_func.go:96` is a **symptom, not the defect**. Deleting that line fixes
nothing, because nothing downstream can accept a context: `LoadedPackage.ExecuteFunction`,
`FunctionTransport.Execute` and the **public** `type Function func(*ExecutionInfo) (FunctionResult,
error)` are all context-free, and `pkg/workflow/ExecutionInfo` has no context field and **no methods at
all** (file:line in Code area).

Item 3 of this task is therefore a **public `pkg/` API change across four hops, not a one-line edit**.
An implementer who reads only the backlog entry will under-scope it badly. It also has direct design
tension with ADR-0027 — see Decisions.

## Decisions

**ADR required, before code.** **ADR-0027** (Async tool invocation via a sub-execution channel,
`Proposed`, 2026-06-02) states that the per-execution runtime capability "MUST be modelled as a second,
typed per-execution runtime port … **injected into orchestrating nodes**, with the worker handle
provided **positionally and adapted in the runtime/transport layer**. It must **not** be added back as a
field on `workflow.ExecutionInfo` (the earlier `Handle any` field was removed precisely to keep that
contract clean — see ADR-0007)."

A-04's instruction "Add the context to `ExecutionInfo`" runs straight into that. The A-04 ADR must pick
one and say why: (i) a `context.Context` is a different kind of thing from a runtime port and is
exempt; (ii) carry it positionally through a typed port as 0027 prescribes; or (iii) supersede 0027's
constraint. **Do not settle this silently in code.** Also interacts with **ADR-0020** (Observability)
and **ADR-0007** (Agent reasoning loop & tools-from-functions). Next free ADR number is 0035
(coordinate with A-03, A-05, A-11). Public `pkg/` API change → the changelog rule applies, but **there
is no CHANGELOG file in this repo**; raise it with the maintainer rather than inventing a destination.
