## What the backlog says

> `ai/agent` and `ai/chat` exist as async functions. Bind them to registry capabilities so an agent's
> tool set is declared, versioned, and traced identically to a node call. An agent invoking a
> capability must be indistinguishable, in the journal and in the trace, from a graph node invoking
> it.

## Premise status

Split it in two, because only one half is knowable now.

- **The gap is READ-confirmed, not executed.** `V-a` records the control flow: `agent_tools.go:86`
  (`InvokeTool`) calls `LoadedPackage.ExecuteFunctionSync` (`loaded_package.go:50`) and never enters
  `internal/actors/workflow_func.go`, the only creator of the `node.execute` span (`:90`) and the only
  caller of `recordNodeDuration` (`:181`). The `capability-registry-and-agents` pack's parity table
  extends it: **no span, no journal entry, no metric, no retry policy, no timeout** on the tool path.
  The only durable record of a tool call is the opaque `steps` array inside the agent node's single
  `step:completed`.
- **The binding is net-new.** There is nothing to reproduce about "bind to registry capabilities" —
  no registry exists yet to bind to.

Stage 1's job is therefore the **executed** version of V-a: one agent tool call and one graph node
call of the same function, asserting the first produces zero `node.execute` spans and zero
`fuse_node_exec_duration_seconds` samples while the second produces both. That test is the acceptance
criterion the binding must later satisfy, and it survives whatever B-03 decides.

Two traps from the pack that a binding predicate will hit: `isExposableTool`'s
`Metadata.Transport == transport.Internal` clause is **vacuously true** (`loaded_package.go:70`
hardcodes it), so the real discriminator is the nil-transport check; and the current catalog excludes
`system/sleep`, `system/wait`, `system/subworkflow`, `system/foreach` by denylist — an agent cannot
open a gate or spawn a sub-workflow today.

## Route

1. `fuse-premise-verifier` — the executed V-a contrast above. Runnable now.
2. **Wait for B-03.** Do not design the binding ahead of the registry; B-03's ADR owns the parity
   contract and this task implements it.
3. `fuse-engine-researcher` — how a tool call could acquire a journal handle. Today it cannot:
   `ExecutionInfo` carries only `WorkflowID`/`ExecID`/`Environment`/`Input`/`Finish`.
4. `fuse-implementation-planner` → `fuse-go-implementer` → `fuse-code-reviewer`.

**HARD GATE.** Routing tool calls back through the actor system *is* an agent-execution-model choice.
The backlog forbids making one before F-02 is green. If the fix stays instrumentation-only the gate
does not bite; if it moves the call onto the node path, stop and say so.

## Decisions

No ADR of its own — **B-03's ADR owns the parity contract** and C-01 implements it. Interacts with
**ADR-0007 · Agent reasoning loop & tools-from-functions**, **ADR-0024 · Function packages: registry
with declarative metadata**, **ADR-0020 · Observability: metrics, tracing, execution traces**, and
the two Proposed ones this design must resolve rather than inherit: **ADR-0026 · Agent-as-orchestrator

per-execution port and explicitly forbids re-adding a field on `workflow.ExecutionInfo`).
