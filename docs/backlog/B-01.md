## What the backlog says

> A written spec, versioned, in the repo, that an SDK author who has never read the engine can
> implement. Existing raw material: `NewFunctionResultAsync`,
> `POST /v1/workflows/{workflowID}/execs/{execID}`, `pkg/transport/type.go` constants,
> `ExecutionInfo{WorkflowID, ExecID, Environment, Input, Finish}`. None of it is documented as a
> contract, and `PackagedFunction.Function` is `json:"-"`, so API-registered functions are
> metadata-only today (`MapToRegistryPackage` → "function %s has no transport").
>
> The spec must settle:
>
> 1. **Push or pull.** […] **Recommendation: push first**, with pull as a later transport […]
> 2. **Invocation envelope** — `workflowId`, `execId`, `nodeId`, `threadId`, attempt, idempotency key,
>    deadline, environment, input, callback URL, `traceparent`.
> 3. **Ack semantics** — sync result vs `202 + async callback`. […]
> 4. **Completion** — success, business error (routes to the error edge), infrastructure error
>    (retryable), and the distinction between them. […]
> 5. **Delivery guarantee** — the A-03 decision, stated plainly, with the idempotency key SDKs dedupe on.
> 6. **Auth** — how a worker proves identity and how FUSE proves it is FUSE. Both directions […]
> 7. **Capability declaration** — input/output schema, so a registered node is typed and
>    `applyFlowMapping`'s coercion (`internal/typeschema/parse.go`) still works.
> 8. **Versioning** — of the protocol itself and of a registered capability.

Plus the standing rule: "**The protocol spec is a contract.** Once B-01 is published and an SDK exists,
changing it breaks strangers."

## Premise status

**net-new.** There is no defect to reproduce and `fuse-premise-verifier` has no work here. What *is*
confirmed by reading (`remote-node-protocol` § TODAY) is the **absence**: `HTTP` (`pkg/transport/type.go:9`)
is never read by production code, `gRPC` (`:10`) is lowercase and therefore unexported dead code,
`MapToRegistryPackage` hardcodes `Transport: transport.Internal` (`internal/packages/loaded_package.go:70`),
and dispatching a metadata-only function fails at `loaded_package.go:41` with `function %s has no
transport`. The callback route exists and validates nothing.

None of that is a capability. **Do not describe any of it to a user as something FUSE does** — it is
raw material the spec is written on top of.

## Route

**Inverted pipeline — spec first, no planner, no Go.** The backlog says "do this before writing any Go".

1. `fuse-protocol-spec-author` — the only agent invoked. Its operating procedure already mandates
   loading `remote-node-protocol`, re-confirming the inventory itself, proposing (not inventing) the
   document location, driving all eight decisions to an explicit answer, and writing the ADR. It writes
   **Markdown only**.
2. Maintainer confirms the spec's home directory and any `OPEN QUESTIONS` it returns.
3. Then, and only then, B-02/B-03/B-05/B-08 route to `fuse-implementation-planner` → `fuse-go-implementer`.

Do **not** invoke `fuse-implementation-planner` first: it plans Go against a clause that already exists.

## Done when

The backlog gives no "Done when"; these are its eight decisions restated one per checkbox, plus the
spec-quality requirements from `fuse-protocol-spec-author`'s own contract. **None may read "TBD".**

- [ ] 1 · Push or pull decided explicitly, with the rejected alternative and why (backlog recommends push first).
- [ ] 2 · Invocation envelope: every field and type listed, each marked as carried by the engine today or not.
- [ ] 3 · Ack semantics: sync result vs `202` + callback — URL, body, status codes, and what a worker does when the callback itself fails.
- [ ] 4 · Completion taxonomy: success / business error / retryable infrastructure error, with the wire representation that distinguishes them.
- [ ] 5 · Delivery guarantee stated plainly (the A-03 decision) with the idempotency key's derivation and who dedupes.
- [ ] 6 · Auth in **both** directions: scheme, headers, replay protection, clock skew, credential storage.
- [ ] 7 · Capability declaration: schema shape, the declarable type set, and what happens to input/output **edge** metadata.
- [ ] 8 · Versioning of the protocol **and** of a registered capability, with negotiation and the in-flight-run rule.
- [ ] Spec is versioned, every clause marked `NORMATIVE`/`INFORMATIVE`, with clause ids a B-05 test can cite, and an appendix recording the engine inventory by `file:symbol`.
- [ ] ADR written from `docs/adr/template.md` with an index row in `docs/adr/README.md`.
- [ ] Every engine gap the spec creates is filed as a backlog item with the clause id attached — not patched.
- [ ] The document's home directory is confirmed by the maintainer before it is created.

  the `remote-node-protocol` pack's inference — file it with evidence rather than fixing it here.

## Decisions

**ADR required** — `fuse-protocol-spec-author` writes it as part of this task. Next free number is
**0035**; A-03, A-04, A-05, A-09 and A-11 are all eyeing the same number, so coordinate. Interacts with
**ADR-0024** (Function packages: registry with declarative metadata — already says out-of-process
functions "await an HTTP/gRPC transport implementation … a separate future decision"), **ADR-0022**
(Retry and error-handling model), **ADR-0023** (Timeout enforcement via actor timers), **ADR-0017**
(Idempotent triggering — dedup is trigger-level only), and **ADR-0027** (Async tool invocation, Proposed
— forbids re-adding a per-execution runtime handle to `workflow.ExecutionInfo`).

Full SpecKit ceremony is not indicated: the deliverable is one versioned document plus an ADR.

The backlog's "public API changes need a changelog entry" rule applies once the spec is published, and
**there is no CHANGELOG file in this repo** — flag the gap with the maintainer, do not create one.
