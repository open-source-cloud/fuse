## Premise status

**UNVERIFIED as a defect — there is nothing to reproduce; this is construction.** Two supporting facts
are READ, not executed: the single `Resume()` call site with no test caller, and that
`tests/e2e/workflow_resilience_suite_e2e_test.go` starts nothing and kills nothing. Everything the
harness will assert is unobserved under a real SIGKILL — which is why the HARD GATE hangs on it.

**What F-01.2 established that F-02 must supply.** F-01.2 reproduced the duplicate-child chain, but with
stated limits: *no process was killed, no ergo runtime, no Postgres* — "restart" meant rebuilding the
aggregate from the persisted journal. F-02 supplies the real thing: a real binary under
`DB_DRIVER=postgres` with a filesystem object store, SIGKILL between the `subworkflow:started` flush and
the child's completion, restart, then assert **exactly one child per `parent_exec_id`**. Build the
fixture **synchronous**: with `async=true`, `handleSubWorkflowAction` journals `step:completed` at
`workflow_handler.go:936` and the pending state never exists.

## Done when

Backlog's own: *it runs in CI and each scenario is green or has a linked task.*

- [ ] Kill after a completed step — that node does not re-execute; no duplicate `step:completed`.
- [ ] Kill with a pending async node — the run completes once; the pre-crash execID callback is neither orphaned nor double-applied.
- [ ] Kill with a pending `system/subworkflow` — **exactly one** child per `parent_exec_id` after restart.
- [ ] Kill with a pending `system/sleep` — wake-up at the original deadline, not full duration from restart.
- [ ] Kill with a pending awakeable — the pre-crash token still resolves; exactly one pending row.
- [ ] Kill a multi-thread run between thread completions — every branch reaches its terminal node.
- [ ] Three restarts on one run — journal length and trace stable across restarts.
- [ ] Each of the seven is GREEN **or** RED with a linked owning task id.
- [ ] It runs in CI (new job in `.github/workflows/e2e.yml`), and skips **loudly** (`t.Skip` naming the missing prerequisite) when Postgres or the binary is absent.

## Out of scope

No engine fixes. A-07 owns duplicate journal append on replay; A-02 replaying the intercepted system
functions; A-03 pending-remote-step semantics; C-12 multi-thread resume; C-09 the mid-flight read model
(so mid-run probes use SQL over `journal_entries`, not a new route); C-07 exposing awakeable ids (so the
harness reads the id from SQL). Do not enable HA to "also test claims" — a separate scenario, and it
turns every basic test into a lease-timeout puzzle. Do not weaken or retry a scenario to make it green,
and do not reuse the quarantined `untriggered` re-trigger.
