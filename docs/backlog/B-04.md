## What the backlog says

> Import an MCP server's tools as capabilities. Real customer flows already speak MCP — the reference
> broker assistant is entirely MCP tools returning `{items, systemMessage, userMessage}` — so this is how
> existing agent estates arrive on FUSE without a rewrite.
>
> Consider the inverse (**expose** FUSE capabilities as an MCP server) but do not build both at once;
> ingestion is the one with a customer behind it.

## Premise status

**net-new.** Nothing to reproduce, nothing to close. The `capability-registry-and-agents` pack records
that there is no MCP reference anywhere in engine code.

**The blocker is execution, not description**, and this is the fact that governs scheduling. An MCP tool
maps cleanly onto `ai.ToolDescriptor{FunctionID, MangledName, Description, Parameters}`
(`internal/packages/functions/ai/tools.go:32`), and `ParameterSchemaToJSONSchema` (`:68`) already
converts in the other direction. But an ingested tool has **no code-backed function**, so
`MapToRegistryPackage` registers it metadata-only with a nil `Transport`, and `isExposableTool`
(`internal/packages/agent_tools.go:95`) rejects it — the capability is *visible and un-callable* until
the remote transport exists.

**That makes B-02 a practical prerequisite even though the backlog declares only B-03.** This is the
pack's inference, not a backlog-declared dependency: raise it with the maintainer as a sequencing
question rather than editing the dependency graph.

## Route

**Blocked on B-03** (the registry is what an MCP tool is ingested *into*), and practically on B-02 (an
ingested capability cannot execute without a remote transport).

1. `fuse-implementation-planner` — hand it B-03's registry ADR, the B-01 declaration clause, and the
   execution-blocker note above. Its `OUT OF SCOPE` section must state that exposure is not being built.
2. `fuse-protocol-spec-author` — **only if** ingested capabilities need a declaration or versioning
   clause B-01 did not settle (e.g. a capability "kind", or how an MCP server's own versioning maps onto
   capability versioning). Spec revision, not Go.
3. `fuse-go-implementer` → `fuse-code-reviewer`.

`fuse-premise-verifier` has nothing to verify here; skip stage 1 and say so in the PR body.

## Done when

Derived from the task text; the backlog gives no "Done when" list.

- [ ] An MCP server's tool list can be imported, producing capabilities in B-03's registry — one definition, both projections.
- [ ] An ingested capability is callable end to end (which requires B-02's transport), not merely listed.
- [ ] Name mangling has an explicit rule for server-qualified MCP names, and collisions across two servers are handled deterministically.
- [ ] MCP-declared parameter schemas map onto the declarable type set B-01 decision 7 fixes; unmappable types fail ingestion loudly rather than silently degrading.
- [ ] Credentials for the MCP server resolve per environment through the existing secret seam (ADR-0031), not from inline config.
- [ ] Re-ingesting an unchanged server is idempotent; a changed server updates rather than duplicating capabilities.
- [ ] The inverse direction (FUSE as an MCP server) is explicitly **not** shipped.
- [ ] `make lint && make build && make test` green.

## Out of scope

- **Exposing FUSE capabilities as an MCP server.** The backlog says consider it, do not build both at
  once. If it is wanted, it is a new backlog id.
- **B-03** owns the registry itself and the projection parity requirement.
- **B-02** owns the transport that makes an ingested capability executable.
- **C-01** owns binding the agent node to registry capabilities; **C-03** owns provider routing.
- The `interceptedOrAsyncFunctionIDs` denylist and the `ai`-package exclusion in the tool catalog are
  existing policy — do not widen them to accommodate MCP tools as a side effect.

## Decisions

**Likely a short ADR**, subordinate to B-03's: it records the ingestion-only scope (and why exposure is
deferred), how an MCP tool becomes a capability, the name-collision rule, and how an MCP server's
credentials and versions are held. Next free number is **0035** (coordinate — several tasks are eyeing
it). Interacts with **ADR-0007** (tools-from-functions), **ADR-0024** (registry with declarative
metadata) and **ADR-0031** (Settings, secrets & environments: a SecretStore seam).

No SpecKit spec unless the maintainer scopes MCP as a subsystem rather than an importer.
