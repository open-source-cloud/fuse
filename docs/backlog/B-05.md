## What the backlog says

> One executable test suite any SDK must pass: sync result, async callback, business error, infra error,
> retry with a stable idempotency key, trace propagation, deadline handling, schema validation, restart
> behaviour per A-03.
>
> Written once, run against every language. Without it, three SDKs means three subtly different engines
> and support tickets you cannot reproduce.

## Premise status

**net-new.** Nothing to reproduce. There is no conformance tier in the repo and no protocol for it to
conform to until B-01 publishes.

Two of the nine scenarios cannot be written at all yet, and the plan must say so rather than shipping a
weaker assertion:

- **Infrastructure error is indistinguishable from business error today.** One status
  (`FunctionOutput.Status == FunctionError`) with a free-form `Data["error"]`; timeout, rate-limit
  rejection and "no transport" all synthesise the identical shape. B-01 decision 4 must create the wire
  field first.
- **Trace propagation is blocked on A-04**, whose real scope (F-01.1, REPRODUCED and executed) is a
  four-hop public `pkg/` API change, not a one-line edit.

**Restart behaviour** additionally depends on A-03's decision, which depends on F-02. Note also the trap
that an async dispatch is journalled `step:completed` at `internal/actors/workflow_handler.go:275`
*before* the `Async` check at `:277`, so `findPendingThreads` does not see an in-flight remote call as
pending — the restart scenario must assert whatever A-03 decides, not what seems obvious.

## Route

**Blocked on B-01.** The suite tests clauses; the clauses must exist and be citable.

1. `fuse-protocol-spec-author` — it owns "B-05 conformance-suite semantics" by its own contract. Hand it
   the nine scenarios; get back, per scenario, the clause id under test and the exact observable
   assertion. A scenario with no clause id is a spec gap, not a test to improvise.
2. `fuse-implementation-planner` — with that mapping.
3. **`fuse-e2e-harness-engineer`, not `fuse-go-implementer`.** This is harness-class work: a real
   engine, a real worker, a rig and a CI stage. That is the deviation from the default pipeline.
4. `fuse-code-reviewer`.

Coordinate with F-02's harness owner: the restart scenario should reuse F-02's rig (real binary,
`DB_DRIVER=postgres`, filesystem object store, SIGKILL) rather than inventing a second one.

## Done when

The backlog's own list, one checkbox per scenario, plus the properties that make it a *conformance*
suite rather than a test file.

- [ ] Sync result.
- [ ] Async callback.
- [ ] Business error (routes to the first `OnError` edge, after retries).
- [ ] Infrastructure error, distinguishable from business error (requires B-01 decision 4).
- [ ] Retry with a stable idempotency key across attempts.
- [ ] Trace propagation, in and out (requires A-04).
- [ ] Deadline handling, including what the worker does when its deadline passes.
- [ ] Schema validation — declared types coerce, and mismatches do not silently vanish.
- [ ] Restart behaviour per A-03's decision.
- [ ] Each scenario cites the B-01 clause id it pins.
- [ ] The suite is runnable against an SDK in any language, with no Go dependency in the SDK under test.
- [ ] Wired into CI in a job that runs **before** merge, not only on `main`.

## Out of scope

- **Writing an SDK.** B-06 and B-07 own that, outside this repo. B-05 must land first.
- **F-02** owns the engine's crash-resume harness. Different target: F-02 proves the engine's durability,
  B-05 proves an SDK's conformance. Reuse the rig; do not merge the suites.
- **B-02** owns the transport under test; a conformance failure caused by a missing engine behaviour is a
  B-02 finding, not a suite workaround.
- **A-03** owns the restart semantics; B-05 asserts them, it does not choose them.
- Never widen the quarantined `"untriggered"` retry in `tests/e2e/workflow_fixture_e2e_test.go` to make a
  suite green.

## Decisions

**Neither an ADR nor a SpecKit spec.** The semantics live in B-01's spec; this task is its executable
form. If the suite needs a behaviour the spec does not state, that is a spec revision by
`fuse-protocol-spec-author`, not a decision taken in a test.

Interacts with **ADR-0022** (retry and error handling), **ADR-0023** (timeouts, and its remote-side
caveat) and **ADR-0017** (idempotency scope).
